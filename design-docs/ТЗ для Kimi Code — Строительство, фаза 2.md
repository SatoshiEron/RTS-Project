# ТЗ для Kimi Code: Строительство, фаза 2 — время и очередь

Контекст: фаза 1 уже в main (каталог `js/data/buildings.js`, `tryBuild`/`canAffordBuilding`,
мгновенная постройка). Дизайн: `design-docs/Строительство и развитие — дизайн.md`.
Действующие системы: игровой календарь (`gameDay`, `BALANCE.DAYS_PER_YEAR`,
1 сек = 1 день), недельный экономтик, единая казна, fmtCompact.

## Рамки фазы 2 (строго)

Входит: время строительства (поле `weeks` из BUILDINGS), одна активная стройка
на цель (город ИЛИ провинция), прогресс в UI, отмена с возвратом 50%.
НЕ входит: прокачка городов, повреждения построек, строительство ИИ, ускорение
стройки за доплату. ИИ в этой фазе по-прежнему не строит.

## 1. Модель

- `city.construction` / `prov.construction` — `null` или
  `{ buildingId, startDay, finishDay }`.
- `finishDay = gameDay + BUILDINGS[id].weeks * 7` (игровые дни).
- Инициализация `construction = null` в конструкторе City и в `initFromWorld`
  для провинций (нормализация, как `prov.buildings`).

## 2. Механика (GameState)

- `canAffordBuilding`: новая причина отказа `busy` — цель уже строит.
- `tryBuild`: списывает стоимость, ставит `construction` (постройка НЕ в `buildings`,
  эффектов пока нет), возвращает `{ ok: true, finishDay }`.
- Завершение: проверка раз в игровой день (там, где инкремент `gameDay`, —
  дешевле всего собирать список целей с `construction` при старте тика или
  проходить по городам/провинциям; частота — раз в день, не каждый кадр).
  По `finishDay`: id переносится в `buildings`, применяются отложенные эффекты
  (укрепления: maxHp ×1.5 — перенести это применение из `tryBuild` сюда),
  `construction = null`, лог `🏗️ Достроено: …`.
- `cancelConstruction(target)`: разрешено только владельцу; возврат
  `floor(cost / 2)` в казну, `construction = null`.

## 3. UI

**CityPanel, секция «🏗️ Постройки»:**
- если идёт стройка: строка «🔨 {icon} {name} — осталось {N} нед.» + полоса прогресса
  (простой div-bar по `(gameDay − startDay) / (finishDay − startDay)`);
- кнопка «✖ Отмена (вернётся 50%)» с confirm-поведением: первый клик — кнопка
  краснеет и меняет текст на «Точно отменить?», второй — отмена;
- пока `construction` активна, все кнопки построек disabled с title «Идёт строительство».
**Панель провинции:** то же для фермы/шахты.
Прогресс обновляется при перерисовке панели (она уже периодически обновляется).

## 4. Запреты и консервация

- НЕ трогать: Renderer.js, боевую систему, pathfinding, редактор карт.
- НЕ коммитить — правки в рабочем дереве, коммитит ревизор.
- Числа — только из BUILDINGS (weeks, cost). Возврат 50% — константа
  `CANCEL_REFUND = 0.5` в js/data/buildings.js.
- Сохранить обратную совместимость: город без `construction` (старые объекты)
  трактуется как «ничего не строит».

## 5. Приёмочные тесты (в отчёте — прогон каждого)

1. Старт стройки рынка: золото списано сразу, `buildings` пуст, эффекта нет,
   `finishDay = gameDay + 21`.
2. Повторная постройка на той же цели во время стройки — отказ `busy`.
3. Через 21 день: рынок в `buildings`, доход ×1.25, `construction === null`.
4. Отмена на середине: возврат `floor(cost/2)`, стройка исчезла, повторная
   постройка доступна.
5. Укрепления: maxHp города ×1.5 ТОЛЬКО после завершения (проверить день до
   и день после finishDay).
6. Параллельность: два разных города строят одновременно — обе стройки идут.
7. Провинция: ферма строится независимо от стройки в ближайшем городе.
8. Захват города во время стройки — стройка НЕ должна ломать игру (минимум:
   без исключений; стройка может просто продолжаться/отменяться — выбрать
   простейшее и описать в отчёте).
9. Кнопки disabled во время стройки, прогресс-бар движется.
10. node --check всех изменённых файлов — чисто.
