# Военное влияние и линия фронта — дизайн-документ

Статус: направление утверждено Илнаром 2026-11-25 (по мотивам консультации ChatGPT,
с тремя поправками ревизора). Основа для будущего ТЗ («фаза 1.5», после мержа
строительства фазы 1).

## Проблема

Текущая линия фронта — статичная политическая граница между провинциями разных
владельцев (Renderer.drawFrontline). Она не движется за войсками: наступление
внутри чужой провинции визуально не отражается, пока провинция не захвачена
целиком. Хочется фронт, который «дышит»: проходит через часть провинции,
отступает, обтекает окружения.

## Принципы

1. **Военный фронт ≠ политическая граница.** Фронт — чисто визуальная военная
   система: показывает фактическое положение противоборствующих армий. Владельцы
   провинций, города и территориальный контроль НЕ меняются. Позже захват
   территории станет отдельным процессом, завязанным на присутствие войск.
2. **Не ломать существующее.** Новый файл `js/systems/FrontlineSystem.js` и
   отдельный метод отрисовки. drawFrontline, rebuildTerritoryLayer, слои карты,
   маркеры, стрелки — не трогать.
3. **Фронт следует за армиями, а не за каждым юнитом.** Положение войск и линия
   фронта связаны, но не совпадают: линия инерционна и сглажена.

## Модель военного влияния

Каждый источник влияния создаёт поле, затухающее с расстоянием:

```
I(d) = W · exp(−d / R)
```

- **Источники:** живые юниты обеих фракций + свои города (якоря, см. поправку 2).
- **Вес юнита:** `W = baseW(type) · (unit.men / unit.maxMen)` — отбитая бригада
  давит фронт слабее полной (связка с manpower v2). Черновые baseW: ополчение 0.5,
  пехота 1.0, броня/мех 1.5, артиллерия 1.2 — уточняются тестами.
- **Вес города:** фиксированный якорь (черновик: 2.0 в центре, R больше юнитного
  в ~2 раза) — не даёт фронту исчезать там, где нет войск, и держит линию
  напряжения между столицами.
- **R (радиус влияния):** черновик — 0.05–0.08 карты для юнитов, 0.12–0.15 для
  городов; сверить с fogUnitRadius (0.15) на предмет дублирования.

В каждой точке сетки: `D = I_player − I_ai`. Линия фронта — контур `D = 0`,
но рисуется только там, где `max(I_player, I_ai)` выше порога присутствия
(иначе фронт «висел» бы посреди пустоты между далёкими армиями).

## Поправки ревизора к исходному предложению

1. **Одно поле, не две системы.** Военное поле считается на существующей
   территориальной сетке (territoryFieldRes = 120) — не вводим параллельную
   грид-инфраструктуру. Marching Squares (~100 строк) — только способ извлечь
   контур из сетки, без отдельной «системы контуров».
2. **Якоря-города обязательны.** Фронт, построенный только на юнитах, в RTS
   с десятком подразделений дыряв и скачет. Города дают фоновое влияние, войска
   «выпячивают» фронт вперёд — ощущение HoI4.
3. **Вес = f(live men).** Бонусная глубина бесплатно: связь с личным составом.

## Поведение и краевые случаи

| Ситуация | Поведение |
|---|---|
| Одиночный юнит в тылу | Не перетягивает фронт: порог влияния + малый вес одиночки |
| Армия отступила | Фронт плавно отходит (инерция, см. ниже) |
| Окружение | Локальный контур вокруг котла (Marching Squares даёт все изолинии, в т.ч. замкнутые) |
| Нет противника рядом | Линия не рисуется там (порог присутствия) |
| Юниты уничтожены | Их влияние исчезает на следующем пересчёте |
| Две армии сблизились | Линия проходит между ними |

## Инерция и частота

- Пересчёт поля: 3–4 раза в секунду (не каждый кадр).
- Временн́ое сглаживание: новое поле смешивается с предыдущим
  (`field = lerp(old, new, 0.35)`) — линия плывёт, а не прыгает.
- При отрисовке контур дополнительно сглаживается (Chaikin, как берега кисти воды).

## Отрисовка

- Тонкая непрерывная линия контура `D = 0`; цвет — смешение цветов фракций
  или нейтральный яркий (подбирается визуально).
- Участки активных боёв (рядом fighting-юниты) — ярче/толще.
- Режимы карты: рисуется в политическом; в физическом — скрыта (проверить
  ощущения, возможно опция).
- Существующий drawFrontline (политическая граница) остаётся как есть.

## Фазы

1. **Ф1: поле.** FrontlineSystem: сбор источников, расчёт поля на сетке 120,
   инерция. Без отрисовки. Метрики в консоль.
2. **Ф2: контур.** Marching Squares → полилинии → Chaikin → Renderer. Отдельный
   метод drawMilitaryFrontline.
3. **Ф3: поведение.** Прогон сценариев из таблицы, подбор baseW/R/порогов/инерции.

## Приёмочные тесты (для будущего ТЗ)

1. Наступление: армия игрока движется вперёд → контур смещается в ту же сторону.
2. Отступление: фронт плавно возвращается, без скачков за один пересчёт.
3. Одиночка в тылу: выступ фронта не превышает R одиночки.
4. Окружение: вокруг котла — замкнутый локальный контур.
5. Уничтожение: через один пересчёт влияние юнита исчезает.
6. Пустой участок (нет войск обеих сторон): линии нет или она по якорям городов.
7. Политические границы, территория, слои M/N, стрелки — визуально без изменений.
8. Производительность: пересчёт поля ≤ 2 мс на 30 юнитов.
